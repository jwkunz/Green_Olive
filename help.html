GPS Sky & Signal Simulator v1.0.0 · ← Back to the app
What this is

A single self-contained HTML/JS application that (1) shows which GPS satellites are overhead for a chosen location and time, using live TLE almanac data and full SGP4/SDP4 orbit propagation, and (2) generates a simulated baseband IQ recording (.wav) of the resulting signal — for feeding into SDR/receiver test software, not for RF transmission.

The recording carries a genuinely real, decodable GPS navigation message: real LNAV subframes on L1 C/A and real CNAV framing/CRC/FEC on L2C, built from a real least-squares curve fit of the satellite's actual orbit — not placeholder random bits. See the project roadmap for the full list of what's real vs. simplified, and why.

1 — Location, time & almanac

Setting your observer position

  • Enter latitude/longitude directly, or tap Use my location to fill them from your browser's geolocation (you'll get a permission prompt).
  • Height is your antenna height above the WGS84 ellipsoid, in meters — sea level is roughly 0. It has a small effect on elevation angles; the default (30m) is fine for most uses.

Setting the date/time

Pick any date/time — past, present, or future within the accuracy of the current TLE data (orbit predictions degrade the further you get from the TLE's own epoch, typically good to days, not months). Tap Now to jump to the current moment.

Fetching the almanac

Tap Fetch live almanac to pull current GPS orbital elements (TLEs) from celestrak.org. This requires an internet connection. If the fetch fails (shown as a CDN or network error), you can paste TLE text manually into the box that appears — grab it from the linked CelesTrak page in any browser and paste it in.

TLE-based orbits are propagated with SGP4/SDP4 (the industry-standard model), accurate to roughly 1km for near-term predictions — good for "what's overhead," not for survey-grade positioning.
2 — Sky view

Tap Compute sky view after loading an almanac. This shows:

  • A polar plot (N up) with a dot for every satellite above 5° elevation, sized/positioned by azimuth and elevation.
  • A data table with per-satellite azimuth, elevation, range, Doppler shift, ionospheric/tropospheric delay estimates, a synthetic clock bias, the modeled antenna/atmosphere amplitude factor, and the RMS residual of the real broadcast-ephemeris curve fit (should read a few meters or less — that's confirming the fit converged well).
Recompute any time you change location, time, or almanac data — it doesn't update automatically.

Signal selection

Sample rate

L1 C/A and L2C offer 2.046 / 4.092 / 5.115 MHz options. L5's much higher chip rate needs at least 20.46 MHz to represent properly — the sample rate dropdown filters automatically when you pick L5.

Duration

Any duration is allowed. Above 60 seconds you'll get a confirmation prompt showing the estimated file size, since sample rate × duration × 4 bytes/sample adds up fast (especially for L5).

Front-end realism controls

  • Noise floor — "Realistic" keeps the GPS signal well below the noise floor, matching real life (you won't see satellites in a raw time-domain plot without correlating — that's expected). "Low noise" makes the signal visually obvious for demos.
  • Front-end bandwidth — simulates the receiver's anti-alias/channel-select filter.
  • AGC — automatic gain control, which (realistically) regulates on total incoming power, not the buried GPS signal specifically.
  • ADC quantization — real GNSS front-ends commonly use just 1-3 bit ADCs; this simulates that, with 2-bit as the realistic default.

Tap Generate WAV. Generation runs in a background Worker so the page stays responsive; a progress bar shows each stage (baseband synthesis → filtering → AGC → quantization → WAV encoding). The output file has I on the left channel, Q on the right, standard 16-bit PCM.

4 — Correlator / acquisition proof

After generating an L1 C/A or L2C recording, pick a PRN from the dropdown and tap Run correlator. This runs a real code-phase × Doppler acquisition search — the same principle a real GPS receiver's acquisition engine uses — to prove the signal is actually recoverable from the noise, not just plausible-looking.

Results show the recovered Doppler and code phase next to the known truth values (since this is a simulator, we know the right answer), plus a heatmap of the search grid with the peak highlighted.

L5 correlation isn't supported: its 10.23 Mcps codes make a full-resolution brute-force search roughly 100x more computationally expensive than L1/L2C — well beyond what's practical in a browser without an FFT-based fast-correlation implementation.
Technical notes & honest limitations

This project aims to be as physically real as practical, and documents deviations explicitly rather than hiding them. Highlights:

  • Ephemeris: a genuine Levenberg-Marquardt least-squares fit of real IS-GPS-200 broadcast parameters against SGP4-propagated truth — not a repackaged orbit. Typically converges to sub-meter accuracy.
  • LNAV (L1 C/A): real parity algorithm, real subframe 1/2/3 bit layout, verified via independent encode/decode round trips.
  • CNAV (L2C/L5): real message framing, real CRC-24Q, real rate-1/2 K=7 convolutional FEC (171/133 octal) — all independently verified. The internal 238-bit payload field layout reuses the LNAV field widths as a documented simplification, since the exact real CNAV Table 30-I bit positions couldn't be independently verified from a primary source.
  • Multipath: a single automatic ground-bounce-style reflection per satellite, stronger near the horizon — not a full scenario-configurable multipath model.
  • Clock bias: synthetic per-satellite values (real values require the broadcast message itself, unavailable from TLE data alone), but genuinely encoded into the transmitted message.

Full details: see ROADMAP.md in the project repository.

Troubleshooting
  • "Fetch live almanac" fails — usually a network/CORS restriction in your browser. Use the manual TLE paste fallback that appears.
  • satellite.js fails to load — the app depends on one CDN script; if your network blocks cdn.jsdelivr.net, the app won't be able to propagate orbits. Check your network settings or try a different network.
  • Generation seems slow — expected for large duration × sample rate combinations (especially L5). It runs in a background Worker, so the page itself won't freeze; watch the progress bar.
  • Correlator finds nothing / wrong values — make sure you generated an L1 C/A or L2C recording first (not L5), and that the recording is at least a few milliseconds long.
