Iono/Tropo delays use the Klobuchar model and a simplified tropospheric mapping function; ClkBias is a synthetic per-satellite offset (real clock corrections require the broadcast nav message, not available from TLE data). Amp is the modeled elevation-dependent gain factor applied in the IQ recording. Eph Fit is the max position error of the real broadcast-format ephemeris (fitted via least squares to SGP4 truth, IS-GPS-200/705 parameterization) over its ±1h fit window — this is what's actually encoded into the nav message bits below, not a placeholder.
3. Simulated IQ recording (.wav)
✓ NEW: L5 signal generation (real I5/Q5 XA/XB code generator per IS-GPS-705, NH10/NH20 overlay codes) — select below. L2C (CM/CL codes) and automatic elevation-dependent multipath remain available too.
Real GPS C/A signal power sits well below the noise floor — this sim keeps that ratio, so satellites won't be visible in a raw time-domain plot without correlation, same as a real receiver.
L5's 10.23 Mcps codes need a much higher sample rate than L1/L2C, so file sizes grow roughly 10x for the same duration — even a few seconds can be hundreds of MB.
Signal chain: ideal sum of satellites + thermal noise → front-end bandwidth filter → AGC (regulates on total power, same as real hardware — it can't "see" the buried GPS signal specifically) → ADC quantization. Quantized output is still stored in a standard 16-bit WAV container for compatibility; only a handful of amplitude levels are actually used.
4. Correlator / acquisition proof
Runs a coarse code-phase × Doppler acquisition search against one PRN from the last recording, non-coherently integrating multiple 1ms blocks to pull the signal out of the noise — the same principle a real receiver's acquisition engine uses. Currently supports L1 C/A recordings only (L2C correlation planned).
